# Справка Letterly — help.letterly.app

Сайт справки Letterly: статьи «как сделать» и ответы на частые вопросы.
Сайт статический (готовые HTML-страницы, сервер не нужен), собран на Astro.

## Как запустить у себя

Нужен Node.js 22 или новее.

```
npm install        # один раз — скачать зависимости
npm run dev        # сайт на http://localhost:4321 (поиск здесь не работает)
npm run build      # собрать сайт в dist/ + поиск + проверка ссылок
npm run check      # проверка кода и сборка — запускать перед публикацией
```

## Где что лежит

- `src/content/articles/` — статьи, одна статья = один файл `.mdx`. Имя файла = адрес: `tags.mdx` → `help.letterly.app/tags/`.
- `src/data/faq/` — вопросы на главной, один файл на вопрос.
- `public/images/` — картинки, `public/video/` — видео.
- `src/data/categories.ts` — разделы и группы; `src/data/site.ts` — почта поддержки и ссылки.

## Как устроена статья

В начале файла, между строками `---`, — служебный блок: заголовок, описание, раздел, группа, порядок, платформы, похожие статьи, черновик (`draft`), скрытая (`hidden`), синонимы для поиска.
Если в нём ошибка или ссылка ведёт на несуществующую статью, сайт не соберётся и напишет, что не так.
Дальше — обычный текст и простые блоки: `<Callout>`, `<Steps>`, `<PlatformTabs>`, `<Figure>`, `<Video>` и другие. Примеры — в любой статье и в `src/components/mdx/`.

## Как публикуется

1. Изменения приходят через PR (запрос на изменение).
2. GitHub сам проверяет PR: сайт собирается, ссылки целы. Кто не в списке `.github/maintainers.txt`, может менять только статьи, FAQ, картинки и видео.
3. Роман смотрит PR и сливает кнопкой «Create a merge commit».
4. Vercel сам выкладывает сайт на help.letterly.app.

Перенос статей из старого макета — `scripts/convert.mjs` (как пользоваться — в начале файла; самого макета в репозитории нет).
